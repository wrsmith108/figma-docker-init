### 🛠️ Detection Tools

#### **v0-detector.js** (16 KB, 541 lines)
**Automated detection script with comprehensive analysis**

Features:
- Analyzes package.json for V0 dependencies
- Checks project structure and component organization
- Scans configuration files (components.json, tailwind.config.ts, tsconfig.json)
- Examines import patterns in component files
- Calculates confidence score (0-1 scale)
- Provides detailed breakdown of findings
- Color-coded output for easy interpretation

Usage:
```bash
# Basic usage (current directory)
node v0-detector.js

# Specific project
node v0-detector.js /path/to/project

# Make executable
chmod +x v0-detector.js
./v0-detector.js /path/to/project
```

Sample Output:
```

Confidence Score: 85.3%

  ✓ shadcn/ui components directory found
  ✓ components.json found

Score: Strong: 4, Medium: 4, Weak: 1
Interpretation: VERY LIKELY a V0-generated project
```

## V0 Detection Summary

### Strongest Indicators (90%+ confidence)

| Indicator | Description | Check |
|-----------|-------------|-------|
| **components.json** | shadcn/ui configuration file | `test -f components.json` |
| **components/ui/** | Auto-generated shadcn/ui components | `ls components/ui/` |
| **Multiple @radix-ui packages** | 4+ Radix UI components installed | `grep @radix-ui package.json` |

### Supporting Indicators (60-80% confidence)

| Indicator | Description |
|-----------|-------------|
| **"use client" directives** | React Server Components in components |
| **Lucide React imports** | Icon library specific to V0 |
| **Tailwind CSS** | Styling framework |
| **kebab-case naming** | Component file naming convention |
| **App Router structure** | Next.js 13+ app directory |
| **@/* path aliases** | TypeScript path configuration |
| **clsx + tailwind-merge** | Utility function pattern |

### Confidence Scoring

- **90-100%**: Very Likely V0 (2+ strong + 3+ supporting indicators)
- **70-90%**: Likely V0 (1+ strong + 2+ supporting indicators)
- **50-70%**: Possibly V0-inspired (Next.js + shadcn/ui without V0)
- **Below 50%**: Unlikely V0 project

## V0 Project Characteristics

### Technology Stack
```
Framework:     Next.js 13, 14, or 15 (App Router)
Language:      TypeScript (default)
Runtime:       Node.js
UI Framework:  React 18+
Component Lib: shadcn/ui (copy-paste, not npm package)
Styling:       Tailwind CSS v3 or v4
Icons:         Lucide React
Primitives:    Radix UI
Utilities:     clsx, tailwind-merge, class-variance-authority
```

### Project Structure Pattern
```
project/
├── app/                    # Next.js App Router
├── components/
│   ├── ui/                # shadcn/ui components (from CLI)
│   └── custom/            # V0-generated custom components
├── lib/
├── public/
├── components.json        # ⭐ Key indicator
├── tailwind.config.ts
├── tsconfig.json          # with @/* paths
├── next.config.js
└── package.json
```

### Dependency Patterns
```
Must Have:
- next, react, react-dom
- tailwindcss

Strong V0 Indicators (3+ of):
- @radix-ui/react-* packages
- lucide-react
- tailwindcss-animate
- class-variance-authority
- clsx + tailwind-merge
```

## Code Pattern Recognition

### Pattern 1: Client Component with Hooks
```typescript
"use client"  // First line - React Server Component boundary

import { useState } from "react"
import { Button } from "@/components/ui/button"
import { ChevronDown } from "lucide-react"

export function ComponentName() {
  const [state, setState] = useState(false)
  return <div className="flex gap-4">...</div>
}
```

### Pattern 2: Form with Async Submission
```typescript
const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault()
  try {
    const response = await fetch("/api/endpoint", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ data }),
    })
    // Handle response
  } catch (err) {
    // Handle error
  }
}
```

### Pattern 3: Data Fetching with useEffect
```typescript
useEffect(() => {
  const fetchData = async () => {
    try {
      const res = await fetch("/api/data")
      const json = await res.json()
      setData(json)
    } catch (err) {
      setError(err)
    } finally {
      setLoading(false)
    }
  }
  fetchData()
}, [])
```

## Key Findings

### Security Observations
- V0 implements static analysis for hardcoded secrets
- Generated code may lack comprehensive input validation
- Default error handling is basic
- No built-in authentication framework
- Missing CSRF protection in some patterns
- Rate limiting typically not included

### Architectural Patterns
- Heavy use of React hooks (useState, useEffect, useCallback)
- Event handling with onClick, onSubmit, onChange
- Conditional rendering with ternary operators
- No CSS modules or styled-components
- Pure Tailwind utility classes
- TypeScript with strict mode enabled

### Performance Characteristics
- Can produce large initial bundles
- Components are optimized for readability over bundle size
- Server components help reduce client-side code
- Image optimization handled by Next.js Image component
- Lazy loading not typically included

## Command Reference

### Quick Checks
```bash
# Check for V0-specific files
test -f components.json && echo "Found components.json"
test -d components/ui && echo "Found shadcn/ui directory"

# Count dependencies
grep -c "@radix-ui" package.json

# Find "use client" directives
grep -r "\"use client\"" components/ | wc -l

# List components with kebab-case naming
ls components/ | grep -E "^[a-z].*-.*\.tsx$"
```

### Run Detection
```bash
# Current directory
node v0-detector.js

# Specific path
node v0-detector.js /full/path

# With output redirect
node v0-detector.js /path > detection-results.txt
```

### Analyze Configuration
```bash
# Pretty print components.json
cat components.json | jq .

# View TypeScript paths
cat tsconfig.json | jq '.compilerOptions.paths'

# Check Tailwind config
grep -A 10 "extend:" tailwind.config.ts
```
