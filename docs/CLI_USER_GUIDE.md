## Installation

### Global Installation (Recommended)

Install vibe-to-docker globally to use it from any project directory:

```bash
npm install -g vibe-to-docker
```

### One-time Use (npx)

Run without installation using npx:

```bash
npx vibe-to-docker [command]
```

### Local Installation

Add to your project as a dev dependency:

```bash
npm install --save-dev vibe-to-docker
```

## Quick Start

### Basic Usage

Navigate to your project root and run:

```bash
# Auto-detect project type and generate Docker configuration
vibe-to-docker init

# Or specify a template explicitly
vibe-to-docker basic
```

### Start Your Containers

```bash
cd .vibe-docker
docker-compose up -d --build
```

### View Logs

```bash
cd .vibe-docker
docker-compose logs -f
```

## Command Reference

### `vibe-to-docker init`

Initialize Docker configuration with automatic project detection.

```bash
vibe-to-docker init [options]
```

**Options:**
- `--tool=<tool>` - Specify the source tool explicitly
- `--tool=auto` - Auto-detect project type (default)
- `--template=<template>` - Choose a specific template
- `--force` - Overwrite existing configuration
- `--dry-run` - Preview changes without writing files

**Examples:**
```bash
# Auto-detect and initialize
vibe-to-docker init

# Initialize for Lovable project
vibe-to-docker init --tool=lovable

# Initialize with specific template
vibe-to-docker init --template=fullstack

# Preview without writing files
vibe-to-docker init --dry-run
```

### `vibe-to-docker [template]`

Generate Docker configuration using a specific template.

```bash
vibe-to-docker <template-name>
```

**Available Templates:**
- `basic` - Minimal Docker setup for simple projects
- `ui-heavy` - Optimized for UI-heavy applications
- `fullstack` - Full-stack with backend and database
- `nextjs` - Next.js specific optimizations
- `supabase` - Supabase integration

**Examples:**
```bash
vibe-to-docker basic
vibe-to-docker fullstack
vibe-to-docker nextjs
```

### `vibe-to-docker --list`

List all available templates.

```bash
vibe-to-docker --list
```

**Output:**
```
Available Templates:

  basic
  ui-heavy
  fullstack
  nextjs
  supabase
```

### `vibe-to-docker --help`

Display help information.

```bash
vibe-to-docker --help
# Or
vibe-to-docker -h
```

### `vibe-to-docker --version`

Display version information.

```bash
vibe-to-docker --version
# Or
vibe-to-docker -v
```

## Tool Selection

### Supported Tools

Vibe-to-docker supports projects generated by these AI-powered development tools:

1. **Figma Make** - React/Vite/TypeScript from Figma designs
2. **Lovable** - Multi-framework fullstack applications
3. **V0** (Vercel) - Next.js/React/Tailwind components
4. **Bolt** (StackBlitz) - Full-stack WebContainer projects

### Explicit Tool Selection

Specify the source tool explicitly using the `--tool` flag:

```bash
# For Figma Make projects
vibe-to-docker init --tool=figma-make

# For Lovable projects
vibe-to-docker init --tool=lovable

# For V0 projects
vibe-to-docker init --tool=v0

# For Bolt projects
vibe-to-docker init --tool=bolt
```

### Benefits of Explicit Selection

- **Optimized Configuration**: Tool-specific Docker configurations
- **Better Defaults**: Pre-configured environment variables
- **Framework Detection**: Automatic detection of framework-specific settings
- **Database Integration**: Auto-configure database connections (Lovable, Bolt)

## Automatic Tool Detection

### How It Works

When you run `vibe-to-docker init` without the `--tool` flag, the CLI automatically detects your project type by analyzing:

1. **Package.json Dependencies**: Framework and tool-specific packages
2. **File Structure**: Directory patterns and config files
3. **Configuration Files**: Tool-specific config files
4. **Build Configuration**: Vite, Webpack, Next.js configs

### Detection Signatures

Each tool has a unique signature:

**Figma Make:**
- Vite + React + TypeScript
- Component-based structure
- No backend dependencies

**Lovable:**
- Supabase integration
- Full-stack setup
- Backend API structure

**V0:**
- Next.js framework
- Tailwind CSS
- Vercel-specific configurations

**Bolt:**
- WebContainer structure
- Multiple framework support
- SQLite or external databases

### Detection Confidence

The CLI reports detection confidence:

```bash
$ vibe-to-docker init

Detecting project type...
✓ Detected: Lovable (confidence: 95%)
✓ Framework: React + Vite
✓ Database: Supabase
✓ Backend: Express

Generating Docker configuration...
```

### Manual Override

If detection is incorrect, override with `--tool`:

```bash
vibe-to-docker init --tool=lovable
```

#### Fullstack Template

Complete setup for fullstack applications.

Optimized for Next.js applications.

**Best For:**

### Template Selection Strategy

The CLI automatically selects the best template based on project detection:

| Detected Tool | Framework | Database | Default Template |
|--------------|-----------|----------|------------------|
| Figma Make | React/Vite | None | `basic` |
| Lovable | React/Vite | Supabase | `supabase` |
| V0 | Next.js | Any | `nextjs` |
| Bolt | Any | Any | `fullstack` |

Override automatic selection:

```bash
vibe-to-docker init --template=ui-heavy
```

## Configuration Options

### Environment Variables

All templates generate `.env.example` with project-specific variables:

**Common Variables:**
```env
# Application
NODE_ENV=production
PROJECT_NAME=my-app

# Container Ports
DEV_PORT=3000
PROD_PORT=8080
NGINX_PORT=8888

# Build Configuration
BUILD_OUTPUT_DIR=dist
```

**Tool-Specific Variables:**

**Lovable/Supabase:**
```env
VITE_SUPABASE_URL=your-supabase-url
VITE_SUPABASE_ANON_KEY=your-anon-key
```

**V0/Next.js:**
```env
NEXT_PUBLIC_API_URL=https://api.example.com
```

**Bolt:**
```env
DATABASE_URL=postgresql://user:pass@db:5432/mydb
```

### Customizing Generated Configuration

After generation, customize files in `.vibe-docker/`:

1. **Dockerfile** - Modify build steps, add dependencies
2. **docker-compose.yml** - Add services, configure networks
3. **nginx.conf** - Adjust proxy settings, add SSL
4. **.env** - Set environment-specific values

### Port Configuration

Ports are auto-assigned to avoid conflicts:

- **Development Server**: Default 3000, auto-increment if occupied
- **Production Server**: Default 8080, auto-increment if occupied
- **Nginx Proxy**: Default 8888, auto-increment if occupied

Override in `.env`:
```env
DEV_PORT=5000
PROD_PORT=9000
NGINX_PORT=7000
```

## Troubleshooting

### Common Issues

#### 1. Template Not Found

**Error:**
```
Template "basic" not found!
```

**Solution:**
```bash
# List available templates
vibe-to-docker --list

# Use a valid template name
vibe-to-docker basic
```

#### 2. Port Already in Use

**Error:**
```
Port 3000 is already in use
```

**Solution:**
The CLI automatically finds available ports. If you see this error:

1. Check which ports are assigned in the output
2. Update `.vibe-docker/.env` if needed
3. Run `docker-compose down` to stop conflicting containers

#### 3. Package.json Not Found

**Warning:**
```
Warning: No package.json found in current directory.
Make sure you're in the root of your project.
```

**Solution:**
```bash
# Navigate to project root
cd /path/to/your/project

# Verify package.json exists
ls package.json

# Run vibe-to-docker again
vibe-to-docker init
```

#### 4. Permission Denied

**Error:**
```
Error: EACCES: permission denied
```

**Solution:**
```bash
# Fix file permissions
sudo chown -R $USER:$USER .

# Or run with sudo (not recommended)
sudo vibe-to-docker basic
```

#### 5. Docker Compose Fails

**Error:**
```
ERROR: no configuration file provided
```

**Solution:**
```bash
# Make sure you're in the .vibe-docker directory
cd .vibe-docker

# Then run docker-compose
docker-compose up -d --build
```

#### 6. Build Fails in Container

**Error:**
```
npm ERR! code ENOENT
npm ERR! syscall open
```

**Solution:**

Check your `.dockerignore` file - you might be excluding necessary files:

```bash
# Edit .vibe-docker/.dockerignore
# Remove patterns that exclude required files
```

Ensure `package.json` and `package-lock.json` are NOT in `.dockerignore`.

### Debug Mode

Enable verbose logging:


## Examples

### Example 1: Basic Figma Make Project

```bash
# Navigate to your Figma Make export
cd my-figma-project

# Initialize Docker configuration
vibe-to-docker init --tool=figma-make

# Start containers
cd .vibe-docker
docker-compose up -d --build

# View in browser
open http://localhost:3000
```

### Example 2: Lovable Fullstack Project

```bash
# Navigate to Lovable project
cd my-lovable-app

# Auto-detect and initialize
vibe-to-docker init

# Update Supabase credentials
nano .vibe-docker/.env

# Start all services (app + database)
cd .vibe-docker
docker-compose up -d --build
```

### Example 3: V0 Next.js Components

```bash
# Navigate to V0 project
cd my-v0-project

# Initialize with Next.js template
vibe-to-docker init --tool=v0

# Start Next.js in container
cd .vibe-docker
docker-compose up -d --build

# Access at http://localhost:3000
```

### Example 4: Bolt Multi-Service App

```bash
# Navigate to Bolt project
cd my-bolt-app

# Initialize with fullstack template
vibe-to-docker init --tool=bolt --template=fullstack

# Review generated services
cat .vibe-docker/docker-compose.yml

# Start all services
cd .vibe-docker
docker-compose up -d --build
```

### Example 5: Custom Configuration

```bash
# Initialize with basic template
vibe-to-docker basic

# Customize Dockerfile
nano .vibe-docker/Dockerfile

# Add custom environment variables
cat >> .vibe-docker/.env << EOF
CUSTOM_VAR=value
API_ENDPOINT=https://api.example.com
EOF

# Build with custom config
cd .vibe-docker
docker-compose up -d --build
```

### Example 6: Production Deployment

```bash
# Initialize for production
vibe-to-docker init --template=ui-heavy

# Update production environment variables
nano .vibe-docker/.env

# Build production image
cd .vibe-docker
docker build -t my-app:latest .

# Tag for registry
docker tag my-app:latest registry.example.com/my-app:v1.0.0

# Push to registry
docker push registry.example.com/my-app:v1.0.0

# Deploy to production
docker run -d -p 80:80 \
  --env-file .env \
  registry.example.com/my-app:v1.0.0
```

## FAQ

### General Questions

**Q: What is vibe-to-docker?**

A: Vibe-to-docker is a CLI tool that generates Docker configurations for projects created by AI-powered development tools like Figma Make, Lovable, V0, and Bolt.

**Q: Do I need to know Docker to use this?**

A: Basic Docker knowledge is helpful but not required. The tool generates production-ready configurations with sensible defaults. Check `DOCKER.md` in your `.vibe-docker/` directory for Docker basics.

**Q: Is this only for AI-generated projects?**

A: While optimized for AI-generated projects, vibe-to-docker works with any React, Vue, Next.js, or Svelte project.

### Installation Questions

**Q: Which Node.js version do I need?**

A: Node.js >= 20.8.1 and npm >= 10.0.0 are required.

**Q: Can I use Yarn or pnpm instead of npm?**

A: Yes! The generated Dockerfile can be customized to use any package manager. Edit `.vibe-docker/Dockerfile` to replace `npm` commands.

**Q: Should I install globally or locally?**

A: Global installation (`npm install -g`) is recommended for convenience. Use local installation for CI/CD pipelines.

### Usage Questions

**Q: Where are the Docker files created?**

A: All Docker files are created in a `.vibe-docker/` directory in your project root. This keeps your project clean and organized.

**Q: Can I use multiple templates?**

A: You can re-run the CLI with different templates, but existing files will be skipped. Delete `.vibe-docker/` to start fresh.

**Q: How do I update my Docker configuration?**

A: Either manually edit files in `.vibe-docker/`, or delete the directory and re-run vibe-to-docker to regenerate.

**Q: Can I customize the generated files?**

A: Yes! All generated files are meant to be customized. Edit them to fit your specific needs.

### Tool-Specific Questions

**Q: How does detection work?**

A: The CLI analyzes your `package.json` dependencies, file structure, and configuration files to identify the source tool and framework.

**Q: What if detection is wrong?**

A: Use the `--tool` flag to explicitly specify your project type: `vibe-to-docker init --tool=lovable`

**Q: Does this work with Figma plugins?**

A: This tool is for projects exported from Figma Make (formerly Figma-to-Code), not Figma plugins.

**Q: Can I use this with Supabase?**

A: Yes! Use the `--template=supabase` option or let auto-detection select it for Lovable projects.

### Docker Questions

**Q: How do I stop the containers?**

A: Run `cd .vibe-docker && docker-compose down`

**Q: How do I view container logs?**

A: Run `cd .vibe-docker && docker-compose logs -f`

**Q: How do I rebuild after code changes?**

A: Run `cd .vibe-docker && docker-compose up -d --build`

**Q: Can I deploy to production?**

A: Yes! The generated configurations are production-ready. See the [Production Deployment](#example-6-production-deployment) example.

**Q: How do I add more services (database, Redis, etc.)?**

A: Edit `.vibe-docker/docker-compose.yml` to add additional services. Use the `fullstack` template as a starting point.

### Troubleshooting Questions

**Q: Port 3000 is already in use, what do I do?**

A: The CLI automatically assigns alternative ports. Check the output for assigned ports, or edit `.vibe-docker/.env` to set custom ports.

**Q: The build fails with module not found errors**

A: Check that `node_modules` is in your `.dockerignore` file, and ensure all dependencies are in `package.json`.

**Q: How do I enable hot reload?**

A: Hot reload is enabled by default in development mode. Make sure you're using `docker-compose up` (not `docker build`).

**Q: Can I use this in Windows?**

A: Yes! The CLI works on Windows, macOS, and Linux. Use WSL2 for best Docker performance on Windows.
