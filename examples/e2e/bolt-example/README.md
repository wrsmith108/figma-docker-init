# Bolt Example - Dashboard App

This is a complete end-to-end example demonstrating how to use **vibe-to-docker** with a [Bolt](https://bolt.new) (StackBlitz) generated project.

## Project Overview

This is a dashboard application built with:
- **Remix** - Full-stack web framework
- **React 18** - UI framework
- **Vite** - Build tool and dev server
- **TypeScript** - Type safety
- **Tailwind CSS** - Utility-first styling (via CDN)

This represents a typical project structure generated by Bolt, which uses Remix for full-stack capabilities with modern tooling.

## Project Structure

```
bolt-example/
├── app/
│   ├── routes/
│   │   └── _index.tsx      # Dashboard page
│   ├── root.tsx            # Root layout
│   └── styles.css          # Global styles
├── build/                  # Build output (generated)
├── package.json            # Dependencies and scripts
├── vite.config.ts          # Vite configuration
├── tsconfig.json           # TypeScript configuration
└── .vibe-docker/           # Generated Docker config (after running vibe-to-docker)
```

## Running Without Docker

First, install dependencies:

```bash
npm install
```

Run the development server:

```bash
npm run dev
```

Build for production:

```bash
npm run build
npm start
```

Type checking:

```bash
npm run typecheck
```

## Dockerizing with vibe-to-docker

### Step 1: Install vibe-to-docker

```bash
npm install -g vibe-to-docker
```

### Step 2: Initialize Docker Configuration

From the project root, run:

```bash
vibe-to-docker basic
```

Or for optimized setup:

```bash
vibe-to-docker ui-heavy
```

This will:
1. Detect your project type (Remix + Vite + TypeScript)
2. Auto-detect build output directory (`build`)
3. Generate Docker configuration in `.vibe-docker/`
4. Assign available ports for services
5. Create `.env` from `.env.example`

### Step 3: Review Generated Configuration

Check the `.vibe-docker/` directory:

```
.vibe-docker/
├── Dockerfile            # Multi-stage Docker build
├── docker-compose.yml    # Service orchestration
├── .env                  # Environment variables
├── .env.example          # Environment template
├── nginx.conf            # Nginx configuration
└── DOCKER.md             # Docker documentation
```

### Step 4: Build and Run

Navigate to `.vibe-docker/` and start the containers:

```bash
cd .vibe-docker
docker-compose up -d --build
```

### Step 5: Access Your Application

The application will be available at:
- **Development**: http://localhost:3000 (hot reload enabled)
- **Production**: http://localhost:8080 (Remix server)
- **Nginx Proxy**: http://localhost:8888 (production with caching)

### Step 6: View Logs

```bash
cd .vibe-docker
docker-compose logs -f
```

## Remix-Specific Considerations

### Server-Side Rendering

Remix apps use SSR by default. The Docker setup includes:

- **Development**: Vite dev server with HMR
- **Production**: remix-serve for SSR
- **Nginx**: Reverse proxy for static assets

### Build Output

Remix generates:
- `build/server/` - Server-side code
- `build/client/` - Client-side assets

Both are included in the Docker image.

### Environment Variables

Remix apps often need runtime configuration. Add variables to `.vibe-docker/.env`:

```env
SESSION_SECRET=your-secret-key
DATABASE_URL=your-database-url
API_URL=https://api.example.com
```

## Benefits of Docker

Once Dockerized:

✅ **Consistent Environment** - Same SSR behavior everywhere
✅ **Easy Deployment** - Deploy to any Docker host
✅ **Isolated Dependencies** - No Node version conflicts
✅ **Production-Ready** - Optimized Remix server
✅ **Scalable** - Add databases, Redis, etc.

## Advanced Configuration

### Adding Database

Edit `.vibe-docker/docker-compose.yml`:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    volumes:
      - postgres-data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

volumes:
  postgres-data:
```

### Adding Redis

```yaml
services:
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
```

### Custom Build Args

Modify `.vibe-docker/Dockerfile` to add build-time configuration:

```dockerfile
ARG NODE_ENV=production
ARG API_URL=https://api.example.com
ENV NODE_ENV=$NODE_ENV
ENV API_URL=$API_URL
```

## Troubleshooting

### Build Errors

Ensure TypeScript types are valid:

```bash
npm run typecheck
```

### Port Conflicts

Check `.vibe-docker/.env` for assigned ports. Modify if needed:

```env
DEV_PORT=3000
PROD_PORT=8080
NGINX_PORT=8888
```

### Remix Server Issues

Check logs for server-side errors:

```bash
cd .vibe-docker
docker-compose logs app
```
